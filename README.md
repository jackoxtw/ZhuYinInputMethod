# 逐音輸入法

**逐音輸入法**是一套原生 macOS 台灣注音輸入法，使用 InputMethodKit + Objective-C++ 製作介面，核心查詞、學習與繁簡轉換以 C99 實作。專案不使用 WebView，主詞庫與繁簡資料以唯讀二進位格式載入，目標是維持低常駐記憶體、低 SSD 寫入與快速候選反應。

目前版本：**v0.1.50 / build 53**

一般使用者請直接閱讀 [一般使用者安裝說明](一般使用者安裝說明.md)，不需要編譯專案。

完整更新內容請見 [版本歷程](CHANGELOG.md)。

> 原始網頁版原型仍保留在 `Docs/Reference/`，目前正式開發與安裝版本為 macOS 原生版。

## HTML 線上試用版

HTML 試用版是單檔 Canvas 原型，使用同一份離線詞庫資料，方便在瀏覽器先體驗輸入與候選排序；它不是 macOS 系統輸入法，不會寫入其他應用程式。

- 候選面板採與原生版相同的深色自適應格局：短候選 10 欄、中長詞 5 欄、長詞 4 欄。
- 右側提供「繁／簡」「說明」「清除學習」控制列；按「說明」可查看 v0.1.50 的快速操作。
- 單按 `Shift` 切英文時，未確認注音會取消；已確認中文會先送出。`Shift + 1～0`、`Shift + A～J` 仍優先作為候選快捷鍵。
- 按住 `Option` 時，只有已學習候選會顯示「刪除」；點選即可刪除其排序／自訂詞學習資料。
- 學習資料只保存在該瀏覽器的本機儲存空間；右側「清除學習」可立即清除。

可直接開啟 [Canvas 原型檔](Docs/Reference/台灣注音輸入法_Canvas_單檔版(20260812-065531).html)，或在 GitHub Pages 已啟用時使用頁首的線上試用連結。

## 主要功能

- 台灣注音輸入與候選排序。
- 支援完整聲調、無聲調、聲母縮寫、混合注音查詢與單字 fallback。單符號完整音節（例如 `ㄧ`、`ㄨ`、`ㄩ`）會正確視為完整無聲調音節；最後一個仍在輸入中的音節也支援前綴匹配，例如輸入 `ㄐㄧㄧㄊ` 即可開始顯示「記憶體」。
- 支援**連續注音自動分詞／組句**：不必在每個詞後按 Enter，例如連續輸入 `ㄐㄧㄣㄊㄧㄢㄊㄧㄢㄑㄧˋ` 可直接顯示「今天天氣」。組句不會提前提交前詞，仍保留在 marked text 中供使用者選擇。
- 台灣常用讀音與多音字補強；安裝時可套用 `libchewing-data` 完整資料。
- 候選窗跟隨目前文字游標，支援多螢幕與可視範圍限制。
- 一般注音候選採**自適應欄數**：短候選維持 10 欄；較長詞組自動改為 5 欄或 4 欄，增加每格寬度並支援完整換行顯示。
- Emoji／中文標點候選可依內容自動擴展為 **1～5 行**，每頁最多 50 個。
- `F9` 或候選窗上的「繁／簡」按鈕可切換最終輸出字體；按鈕左上角有小型 `F9` 提示。
- 「繁／簡」按鈕下方提供「說明」按鈕，可開啟不搶焦點的快速操作說明；再次點擊或按 `Esc` 即可關閉。
- 簡體輸出採 **OpenCC 1.3.1 `tw2s`** 邏輯，支援台灣正體異體字與詞組例外。
- 使用者選字與自建詞組學習保存在本機；相同注音查詢會優先顯示上次明確選過的候選，並以批次方式寫入以降低 SSD 寫入頻率。
- 候選長度採**音節數優先**：目前輸入匹配 1／2／3 個音節時，前段優先只顯示 1／2／3 字的完整候選；若有以前真正學習過、且讀音可由目前輸入繼續延伸的較長詞，會接在等長候選之後。一般未學習的較長詞不會混入前段，學習延伸詞依字數由短到長，再依使用頻率與最近使用排序。
- 已學過的多字詞支援**縮寫召回**：查詢先擴大候選池再套學習排序；例如曾選過「資料庫」後，輸入 `ㄗㄌㄎㄨˋ` 仍可把它從較後面的原始詞庫排名拉回候選前段。Composer 亦保留至少匹配 3 個音節的多字詞 edge，避免被大量單字 fallback 淹沒。
- 內建官方品牌詞 **「逐音輸入法」**（`ㄓㄨˊ ㄧㄣ ㄕㄨ ㄖㄨˋ ㄈㄚˇ`）：完整讀音直接列為第一候選；5 音節以上的混合縮寫可使用通用長詞召回，例如 `ㄓㄧㄕㄖㄈ`。短輸入如 `ㄓㄨˊ` 不會強制插入品牌候選。
- `.command` 安裝器使用顏色區隔步驟、資訊、成功、警告與錯誤訊息。

## 系統需求

- **macOS 12 Monterey 或更新版本**。
- Xcode Command Line Tools。
- Apple Silicon 或 Intel Mac；安裝腳本只編譯目前 Mac 的原生架構，不建立額外 universal binary。
- 建議可連線網路，以便安裝時取得完整 `libchewing-data` 與 OpenCC 1.3.1 資料；沒有網路仍可使用 ZIP 內建的核心修正版詞庫。
- 若系統可使用 `python3`，安裝器會自動建立完整台灣讀音與 OpenCC `tw2s` 二進位資料；沒有 `python3` 時會改用內建 fallback。

若尚未安裝 Xcode Command Line Tools，可在 Terminal 執行：

```bash
xcode-select --install
```

## 安裝

## 建立可發佈 Release

開發者要產生給一般使用者使用的已編譯版本時，請雙擊 `建立Release.command`，或在 Terminal 執行：

```bash
./建立Release.command
```

此指令會編譯、產生 `AppIcon.icns`、以 ad-hoc 簽章驗證 App，並更新：

```text
Release/逐音輸入法-v0.1.50/
├── 逐音輸入法.app
├── 安裝逐音輸入法.command
└── 說明.txt
```

它**不會安裝或修改目前 Mac 的系統輸入法**。Release 內的安裝器才會在一般使用者的 Mac 上要求管理員密碼，將 App 安裝到 `/Library/Input Methods/`。

### 方法一：Finder 雙擊

1. 解壓縮專案 ZIP。
2. 雙擊 `build_and_install.command`。
3. macOS 可能要求輸入管理員密碼。
4. 安裝完成後，腳本會自動開啟「系統設定 → 鍵盤」。

### 方法二：Terminal

```bash
cd zhu-yin-input-method-native
./build_and_install.command
```

安裝器會依序：

1. 檢查 macOS、目前 CPU 架構與 Xcode Command Line Tools。
2. 嘗試套用完整 `libchewing-data` 台灣注音／多音字資料。
3. 嘗試使用 OpenCC 1.3.1 官方 `tw2s` 規則建立完整台灣正體→簡體轉換表。
4. 產生 macOS `AppIcon.icns`。
5. 編譯 Core、InputMethodKit、游標定位與候選視窗模組。
6. 進行 ad-hoc codesign 與驗證。
7. 安裝到唯一正式位置：`/Library/Input Methods/逐音輸入法.app`。

8. 重新註冊 LaunchServices 與 InputMethodKit 相關服務。

### 在 macOS 啟用逐音輸入法

安裝完成後：

1. 開啟 **系統設定 → 鍵盤 → 文字輸入 → 編輯…**。
2. 點擊左下角 **`+`**。
3. 選擇 **繁體中文**。
4. 在右側選擇 **逐音輸入法**。
5. 點擊 **新增**。

若剛安裝完沒有立刻出現在清單，可先關閉並重新開啟系統設定；仍未出現時請參考「常見問題」。

### 第一聲（平聲）與 Space

逐音輸入法使用 `ˉ` 顯示第一聲，因此五個聲調符號完整為：`ˉ ˊ ˇ ˋ ˙`。

- 完全沒有注音、候選或待確認文字時，按 `Space` 會直接送出一般空格。
- 輸入尚未標聲調的音節後按 `Space`，會補上第一聲 `ˉ`。例如 `ㄊㄧㄢ` + `Space` → `ㄊㄧㄢˉ`。
- 第一聲符號不是強制輸入；原本連續輸入、不特別補 `ˉ` 的方式仍可使用。
- 若目前組字最後已經是 `ˉ`、`ˊ`、`ˇ`、`ˋ` 或 `˙`，再按 `Space` 會改為選取目前候選，不會重複加入聲調。
- 明確的 `ˉ` 只代表第一聲，不會誤匹配第二、三、四聲或輕聲。
- 學習系統會把第一聲有無顯示 `ˉ` 視為同一個 query identity，避免同一個詞被拆成兩份學習紀錄。

例如：

```text
ㄐㄧㄣ + Space → ㄐㄧㄣˉ
ㄊㄧㄢ + Space → ㄊㄧㄢˉ
```

連續組句也支援第一聲符號，例如 `ㄐㄧㄣˉㄊㄧㄢˉㄊㄧㄢˉㄑㄧˋ` 仍可得到「今天天氣」。

### 快速說明

候選窗右側「繁／簡」按鈕下方有「說明」按鈕。說明採與「清除學習」一致的深色圓角卡片、陰影與按鈕樣式，快捷鍵以按鍵膠囊呈現，並完整列出五聲 `ˉ ˊ ˇ ˋ ˙`。面板採 lazy 建立與 non-activating panel，不會搶走目前 App 的文字輸入焦點；可再次點擊「說明」、按 `Esc`、點右上角 `×` 或底部「關閉」收起。候選窗移動或關閉時，說明面板會同步重新定位或關閉。

## 繁／簡輸出

逐音輸入法的繁簡設計是「**輸入與學習永遠維持台灣正體，只有最終送出時才轉成簡體**」。

因此切到「簡」後：

- 注音輸入規則不變。
- 候選字仍顯示台灣正體。
- 使用者學習資料仍保存台灣正體。
- 按下 Enter／完成組字送出到應用程式時，才執行台灣正體→簡體轉換。
- 繁／簡選擇會透過 macOS `NSUserDefaults` 記住，下次啟動仍保留上次設定。

可使用兩種方式切換：

- 按 `F9`。
- 點擊候選窗右側的「繁／簡」按鈕；按鈕左上角會顯示小型 `F9` 提示。

完整模式在安裝時使用 OpenCC 1.3.1 `tw2s` 的資料建立逐音輸入法自己的離線 `t2s.bin`。安裝完成後，輸入法執行期**不依賴 OpenCC、不需要 Python、也不需要網路**。

例如：

```text
麵       → 面
牛肉麵   → 牛肉面
裡面     → 里面
臺灣發展 → 台湾发展
為了     → 为了
項鍊     → 项链
乾坤     → 乾坤
```

詞組優先規則可避免部分逐字轉換造成的錯誤。

## 連續注音自動分詞與組句

從 v0.1.15 起，逐音輸入法可以把一整串連續注音拆成多個詞，再組成完整候選，不需要每打一個詞就先按 Enter。

例如：

```text
ㄐㄧㄣㄊㄧㄢ
→ 今天

ㄐㄧㄣㄊㄧㄢㄊㄧㄢㄑㄧˋ
→ 今天天氣
```

輸入到尾端音節尚未完成時也會保留已確定的前段，例如：

```text
ㄐㄧㄣㄊㄧㄢㄊ
→ 以「今天…」開頭的後續候選
```

組句器使用合法注音音節邊界，避免把 `ㄐㄧㄣ` 錯切成 `ㄐㄧ｜ㄣ` 之類不合理分段。內部採 bounded beam search：最多 8 個詞段、beam width 32，每個位置最多展開 12 個詞候選，以控制每次按鍵的計算量。

選中組句候選後，內部仍拆回各個正常詞段；只有最後 Enter 確認時才學習各詞與整體詞組，因此不會因為只是瀏覽預測候選就污染學習資料。

### 組句候選品質控制

從 v0.1.18 起，組句排序加入「左側長詞優先 + 整句學習分封頂 + 相對品質門檻」。例如輸入 `ㄒㄧㄢㄗㄞㄧㄡˇ` 時，會優先保留「現在＋有」這類高品質路徑，不再為了填滿候選頁而塞入大量「先在有」「線在有」等僅發音可拼但品質明顯較低的組合。

- 句首若能匹配較長的完整詞，會優先於把同一段拆成單字再接後詞。
- 組句內各詞的 frequency／recency／query／preference 學習分改為**整句各類別封頂**，段數增加不會自動得到更多學習分。
- Composer 原始品質差距不再以 `/20` 壓平，避免低品質路徑被少量學習分輕易反超。
- 完整尾音節採嚴格相對品質門檻；未完成尾音節則使用較寬門檻保留輸入中的預測選項。如果只有少數候選夠好，就只顯示少數候選，不強制填滿 20 個。
- 明確學習過的完整使用者詞組仍走獨立 phrase-learning 路徑，因此自訂名稱或特殊用語不會被此品質門檻移除。

### 長組句候選的自適應顯示

從 v0.1.16 起，候選窗不再把長組句硬塞進固定 10 欄。版面會依目前頁面最長候選自動調整：

- 1～2 字：10 欄，維持原本緊湊單字候選。
- 3～5 字：5 欄，增加候選格寬度。
- 6 字以上：4 欄，使用更寬的候選格與較高列高。
- 長文字以中文逐字換行完整顯示，不使用省略號 `…` 隱藏內容。
- 字體最低維持 12 pt；不會為了塞進固定格子而無限制縮小。
- 候選格有 clipping 保護，文字不會再蓋到隔壁候選。
- ↑／↓ 會依目前實際欄數移動，因此 5 欄版面一次上下移動 5 格、4 欄版面一次移動 4 格。
- Emoji／中文標點仍維持既有 10 欄、最多 5 行的特殊候選布局。

候選資料本身不會被裁掉；顯示與實際選取／送出的文字保持一致。

## 台灣注音與多音字詞庫

ZIP 內建的 `Shared/Resources/dictionary.bin` 已包含核心台灣讀音修正，目前為：

- **76,724** 個詞條。
- 約 **1.76 MiB**。
- 使用唯讀 `mmap` 載入。

安裝時若網路與 Python 可用，`build_and_install.command` 會下載 `libchewing-data` 的 `word.csv`，在不破壞既有詞 ID 的前提下：

- 修正台灣常用讀音。
- 補入單字多音讀法。
- 保留原有詞庫排序與學習 ID 相容性。
- 在 Taiwan reading overlay 後重新套用 `Shared/Resources/brand_words.csv`；因此完整線上詞庫與離線 fallback 都會保留「逐音輸入法」品牌詞。

若完整資料下載或驗證失敗，安裝器會顯示黃色警告並使用 ZIP 內建的核心修正版，不會因網路問題中止整個安裝。

## 資料寫入與隱私

逐音輸入法不會把使用者輸入內容上傳到網路。網路只在**安裝／建置階段**用來取得公開的詞庫與 OpenCC 資料。

### 使用者學習資料

候選學習只在文字 **Enter 最終確認送出後**生效；單純移動候選游標、打開候選窗或取消組字都不會學習。v0.1.12 起改採「**有限長期頻率 + 近期使用 + 有效期查詢偏好**」：

- 一次 Enter 只算一個 learning event；同一次送出的多個字／詞不會讓學習時鐘重複前進。
- 一般字詞長期頻率最多按 31 次計分（最高 +124,000），避免歷史高頻永久壟斷。
- 一般字詞最近使用最高 +120,000，30 個 learning events 內逐步衰退。
- 同一注音的查詢頻率最多按 8 次計分（最高 +40,000）。
- 同一注音最近明確選過的字典候選會取得最高 `preference_rank=2`；64 個 learning events 未再選後，強制優先失效並回到一般分數競爭。
- 已學習的精確使用者詞組使用 `preference_rank=1`；詞組頻率最多按 16 次計分（最高 +128,000），另有最高 +160,000 的近期分數，32 個 events 後歸零。
- 同一組注音若改選另一個字典候選，新的選擇會立即取代舊的 query preference。
- v0.1.22 起，Runtime 先召回 256 個原始字典候選、套用個人學習與長縮寫柔性優先後，再截成前 128 個進入組句／使用者詞組合併；曾選過、且本次完整對上至少 2 個音節的多字詞仍會取得 `preference_rank=1` 的柔性召回優先；5 音節以上、已碰到全部音節的長縮寫也會取得同級柔性優先。明確同 query 的最近選擇仍維持更高的 `preference_rank=2`。
- v0.1.21 起，已學過的多字詞若已匹配到全部音節、只是最後一個音節仍在輸入中，也可取得同一級柔性召回優先；例如 `ㄗㄌㄎ` 可提前召回「資料庫」，但只輸入 `ㄗㄌ` 時不會過早強推。
- 舊版 `learning_A.dat` / `learning_B.dat` 可直接沿用；舊 count 不會被清除，只是在計分時套用新上限。

學習資料儲存在：

```text
~/Library/Application Support/逐音輸入法/learning_A.dat
~/Library/Application Support/逐音輸入法/learning_B.dat
```

採 A/B snapshot + CRC 設計：

- 一般打字、選字與候選排序只修改 RAM。
- 累積至少 32 次 dirty mutation，或距上次保存至少 15 分鐘且有變更，才允許批次寫入。
- 正常程式結束時才做一次強制同步。
- 主詞庫 `dictionary.bin` 與繁簡表 `t2s.bin` 執行期永遠唯讀。

### 游標定位診斷

為了診斷候選窗位置，最多會在 `/tmp/zhu-yin-caret.log` 記錄 100 筆定位來源與座標，例如：

```text
IMK-lineHeight x=512.0 y=420.0 w=0.0 h=24.0
```

此檔**不記錄使用者輸入文字**，只包含定位來源與 x/y/w/h 座標；重新開機後 `/tmp` 通常會被系統清理。

## 常見問題

### 安裝完成，但「逐音輸入法」沒有出現在新增輸入來源清單

先確認正式安裝檔存在：

```bash
ls -ld "/Library/Input Methods/逐音輸入法.app"
```

然後關閉並重新打開「系統設定 → 鍵盤 → 文字輸入」。若仍未出現，可登出 macOS 再登入。

### 候選窗沒有跟隨文字游標

先輸入幾個注音後查看診斷：

```bash
cat /tmp/zhu-yin-caret.log
```

常見來源包括：

- `IMK-lineHeight`：InputMethodKit 原生候選定位來源。
- `firstRect`：NSTextInput 相容 fallback。
- `AX`：Accessibility fallback。
- `cached`：暫時沿用最近一次有效座標。
- `emergency-center`：所有即時定位來源都失敗。

若完全沒有此檔案，可能仍在執行舊版輸入法或新 bundle 尚未真正載入。

### 如何確認安裝的是新版二進位檔

可檢查目前安裝的版本：

```bash
/usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' \
  "/Library/Input Methods/逐音輸入法.app/Contents/Info.plist"
```

目前應顯示：

```text
0.1.21
```

### OpenCC 或 libchewing-data 下載失敗會不能安裝嗎？

不會。安裝器會顯示黃色警告並退回 ZIP 內建的核心修正版資料；輸入法仍可編譯與安裝。完整網路資料主要用於擴大台灣讀音、多音字與繁簡詞組覆蓋率。

### 為什麼簡體模式的候選仍是繁體？

這是刻意設計。逐音輸入法以台灣正體作為唯一內部詞庫與學習格式，只有文字真正送出至應用程式前才轉成簡體，可避免繁簡兩套詞頻資料互相污染。

## 清除個人學習資料

候選窗右側提供 **「清除學習」**。在最小高度時維持既有位置；當候選窗因 4～5 行候選而變高時，「清除學習」會固定貼齊右側控制欄最底部，與上方「繁／簡」「說明」保留明顯安全距離，並在空間足夠時顯示分隔線，降低誤觸風險。按下後不會立即刪除，而是顯示在候選窗前方的**非 Modal 自訂確認面板**；只有明確點擊 **「清除學習資料」** 才會執行，點「取消」或按 Esc 都只會關閉確認面板。確認流程不使用 `NSAlert runModal`，因此不會因警告視窗藏在其他視窗後方而鎖住整個輸入法。

清除範圍包含 `learning_A.dat`、`learning_B.dat`、最近使用、常用詞頻、Query Preferred、自訂學習詞組與已學詞縮寫召回依據。清除成功後立即生效，不必重新啟動輸入法；同一個確認面板會顯示「學習資料已清除」後自動收起，不再建立第二個 modal 視窗。

**不受影響**：內建字典、完整台灣詞庫、`Shared/Resources/brand_words.csv`（包含「逐音輸入法」品牌詞）、OpenCC、繁／簡設定、Emoji、中文標點與其他 UI 設定。


### 候選面板滑鼠互動

候選面板使用 non-activating `NSPanel`，可直接用滑鼠選候選、切換繁簡、開啟說明與清除學習，同時不把鍵盤焦點從目前輸入中的 App 搶走。候選 view 不要求 panel 成為 key，也不把滑鼠按下誤判為拖曳視窗。

### 滑鼠候選面板事件鏈

候選面板採 View → Panel → InputController 的明確事件轉送；controller 持有 panel，而 panel 的 delegate 使用 weak 引用，避免 retain cycle。
