# 組句候選品質過濾設計

## 目標

降低連續注音組句產生的「發音可拼、中文不自然」候選，同時保留完整詞庫、連續組句、使用者學習與低記憶體特性。

## 核心規則

1. **左側長詞優先**：句首可匹配較長完整詞時，優先於把前綴拆成單字後再接後詞。例如 `現在 + 有` 應明顯優於 `先 + 再有`。
2. **學習分整句封頂**：composition constituent 的 frequency、recency、query、preference 分別封頂，不能因為切成更多段就累積更高總學習分。
3. **保留 Composer 品質差距**：Runtime 不再用 `/20` 壓平 Composer 分數。
4. **相對品質門檻**：完整尾音節使用嚴格門檻；尾音未完成時使用較寬門檻，兼顧乾淨結果與即時預測。
5. **少而準**：不要求填滿候選頁，最多接納 8 個 composition 候選。
6. **自訂詞不受影響**：明確學習過的完整 user phrase 使用既有 phrase-learning 路徑，不受 composition 品質門檻刪除。

## 參數

- 完整組句品質視窗：8,000
- 未完成尾音品質視窗：60,000
- composition runtime 最多接納：8
- frequency cap：124,000
- recency cap：120,000
- query cap：40,000
- preference cap：120,000

## 代表案例

- `ㄒㄧㄢㄗㄞㄧㄡˇ` → `現在有`
- `ㄊㄚㄗㄞㄐㄧㄚ` → `他在家 / 她在家 / 它在家`
- `ㄐㄧㄣㄊㄧㄢㄊ` → 保留多個 `今天…` 尾音未完成預測

## 記憶體

不新增大型語言模型、n-gram 檔案或 persistent table；只增加常數與既有候選分數運算，因此常駐記憶體增加可忽略。
